How OpenShell controls Reachy on the Thor

What happens between typing "Reachy, look up" and the motors moving, which process does each step, and which file to open to see it.

The path of one request

Everything runs on the Jetson Thor except the model. Dashed green is the sandbox boundary. Nothing inside it can reach the network, the robot, or the API key except through the OpenShell gateway.

Step by step

Paths below are relative to ~/Desktop/mkarp.

  1. You type a sentence. talk.sh runs openshell sandbox exec, which relays the command into the VM and runs the test entry point there. talk.sh · agent/minimal_agent.py (copied to /sandbox/minimal_agent.py)
  2. The agent builds the request. It loads the 13-line system prompt, attaches the three tool schemas, and appends your sentence. agent/minimal_agent.py: SYSTEM_PROMPT and TOOLS
  3. The request leaves the sandbox toward the model. OpenShell checks the calling binary and destination, then the provider proxy replaces the placeholder key with your real NVIDIA key. The key never exists inside the VM. openshell/reachy-nvidia.yaml · openshell provider get reachy-nvidia
  4. The model answers with a tool call, for example move_head(directions=["up"]). The schema's enum means it can only ever say one of five words. agent/minimal_agent.py: ask()
  5. Python turns the word into a fixed pose. "up" becomes pitch -30°, yaw 0°, one second, minjerk. It sends POST /api/move/goto to host.openshell.internal:8000. agent/minimal_agent.py: POSES and move_head()
  6. OpenShell decides. The active policy either has an allow rule for that method and path or it does not. Denied returns a 403 with a readable reason. Allowed forwards the request to the daemon on the host. openshell/policy-*.yaml · openshell logs reachy-agent shows ALLOWED / DENIED lines
  7. The daemon moves the head. It solves the six motor angles, runs a 50 Hz control loop, and writes servo packets over USB serial. robot/venv/lib/python3.12/site-packages/reachy_mini/daemon/app/routers/move.py · start-daemon.sh
  8. The result goes back to the model, which writes the reply you see: "Nod completed" or "OpenShell policy blocked the request". It does not retry a denial. agent/minimal_agent.py: end of main()

Why the split matters. The model handles fuzzy language but can only emit one of five words. Python owns the numbers. OpenShell owns the yes/no on the endpoint. No prompt injection can turn "look up" into a raw motor command, because the sandbox has no path to /api/move/set_target or the motor routes at all.

Try it

Deny, then allow, same sentence:

openshell policy set reachy-agent --policy openshell/policy-motion-disabled.yaml --wait
./talk.sh "Reachy, look up"          # -> policy_denied, robot still
openshell policy set reachy-agent --policy openshell/policy-motion-enabled.yaml --wait
./talk.sh "Reachy, look up"          # -> completed, robot moves
openshell logs reachy-agent | grep -E "DENIED|ALLOWED" | tail
