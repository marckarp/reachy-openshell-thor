How OpenShell controls Reachy on the Thor

What happens between typing "Reachy, look up" and the motors moving, which process does each step, and which file to open to see it.

The path of one request

Everything runs on the Jetson Thor — including the model (vLLM on port 8001). Dashed green is the sandbox boundary. Nothing inside it can reach the network, the robot, or port 8001 except through the OpenShell gateway.

Step by step

Paths below are relative to ~/Desktop/mkarp.

  1. You type or speak. talk.sh passes a sentence; voice.sh and robot/listen.py record the robot mic and base64-pipe a WAV on stdin. Either way openshell sandbox exec relays it into the VM. listen.py keeps the mic open and uses Silero VAD (host CPU) to cut one WAV per utterance. talk.sh · voice.sh · robot/listen.py · agent/minimal_agent.py (copied to /sandbox/minimal_agent.py)
  2. The agent builds the request. It loads the system prompt, attaches the two tool schemas, and appends your sentence, or an input_audio part holding the WAV. Omni has an audio encoder, so no separate speech-to-text model exists anywhere. In audio mode the prompt adds: if not addressed as Reachy, reply IGNORE. agent/minimal_agent.py: SYSTEM_PROMPT, AUDIO_PROMPT, TOOLS, user_message()
  3. The request leaves the sandbox toward the model. OpenShell checks the calling binary and destination. The local-vllm provider has no API key — it only grants the sandbox permission to reach port 8001 on the host where vLLM is running. openshell/local-vllm.yaml · openshell provider get local-vllm
  4. The model answers with a tool call, for example move_head(directions=["up"]). The schema's enum means it can only ever say one of five words. agent/minimal_agent.py: ask()
  5. Python turns the word into a fixed pose. "up" becomes pitch -30°, yaw 0°, one second, minjerk. It sends POST /api/move/goto to host.openshell.internal:8000. agent/minimal_agent.py: POSES and move_head()
  6. OpenShell decides. The active policy either has an allow rule for that method and path or it does not. Denied returns a 403 with a readable reason. Allowed forwards the request to the daemon on the host. openshell/policy-*.yaml · openshell logs reachy-agent shows ALLOWED / DENIED lines
  7. The daemon moves the head. It solves the six motor angles, runs a 50 Hz control loop, and writes servo packets over USB serial. robot/venv/lib/python3.12/site-packages/reachy_mini/daemon/app/routers/move.py · start-daemon.sh
  8. The result goes back to the model, which writes the reply you see: "Nod completed" or "OpenShell policy blocked the request". It does not retry a denial. agent/minimal_agent.py: end of main()
  9. The host speaks the reply. voice.sh / listen.py read the [reply] line and call POST /say on the trusted speaker service, which runs Kokoro TTS on the host CPU and plays it on the robot speaker. The policy allows the sandbox only POST /play on that port; a sandbox call to /say gets 403. IGNORE replies are dropped silently. robot/speaker.py: say() · robot/models/kokoro-v1.0.onnx

How audio goes in and out

Audio is never streamed to the model. It moves as one clip per sentence, and only the host touches the mic and speaker. Top lane: your voice going in. Bottom lane: the reply coming out.

Software at each hop

HopSoftwareWhat it does
Capturearecord (ALSA)Keeps the USB mic open, raw 16-bit PCM at 16 kHz mono, piped to Python
SlicingSilero VAD v5, ONNX Runtime, CPUPer 32 ms slice: probability that someone is speaking. Starts a buffer above 0.5, cuts the clip after 0.7 s below 0.35. Knows no words.
Transport inbase64 + openshell sandbox exec stdinThe only way bytes enter the VM. Text-safe, byte-exact (verified with md5).
Requestopenai Python client inside the sandboxOne chat.completions call; the WAV rides as {"type":"input_audio","format":"wav"}
Listening + thinkingNemotron 3 Nano Omni 30B-A3B NVFP4 on vLLM 0.31 (GPU)Built-in Parakeet-style audio encoder turns the clip into tokens; the same LLM decides IGNORE / tool call / answer. No separate STT.
Transport outstdout of the exec[reply] ... line, read by the host
SpeechKokoro-82M, ONNX Runtime, CPU, inside robot/speaker.pyText to 24 kHz WAV in about half a second per sentence
Playbackaplay (ALSA)Same USB card as the mic. listen.py keeps the mic closed until playback ends.
  1. Mic stays open on the host. arecord reads the robot's USB audio card at 16 kHz mono. Silero VAD (2 MB ONNX, CPU) scores each 32 ms slice as speech or not. Nothing leaves the host while the room is quiet. robot/listen.py: VAD, capture_utterance()
  2. One sentence becomes one WAV. Speech starts: buffer, with 0.3 s of pre-roll. 0.7 s of silence: cut. The clip is base64 text, piped on stdin through openshell sandbox exec into the VM. A 4 s clip is about 128 KB. robot/listen.py: turn() · voice.sh does the same with a fixed 4 s recording
  3. The model listens to the file. The agent puts the WAV in a single chat request as an input_audio part. Omni's built-in audio encoder turns it into tokens; the same LLM then reasons, picks move_head or answers, or replies IGNORE if you were not talking to it. There is no separate speech-to-text model. agent/minimal_agent.py: user_message(), AUDIO_PROMPT
  4. Text comes back out. The reply leaves the sandbox the only way anything does: printed on stdout as [reply] .... The host reads it. robot/listen.py: turn()
  5. The host speaks. POST /say to the trusted speaker service. Kokoro (CPU, about half a second per sentence) renders a WAV, aplay sends it to the same USB card. The mic is closed during playback so Reachy does not hear itself, then reopens. robot/speaker.py: say()

Consequences: 1 to 2 s between the end of your sentence and the answer, no barge-in or mid-sentence reaction, and the sandbox never sees an audio device, only a WAV on stdin.

Why the split matters. The model handles fuzzy language but can only emit one of five words. Python owns the numbers. OpenShell owns the yes/no on the endpoint. No prompt injection can turn "look up" into a raw motor command, because the sandbox has no path to /api/move/set_target or the motor routes at all.

Try it

Deny, then allow, same sentence:

openshell policy set reachy-agent --policy openshell/policy-motion-disabled.yaml --wait
./talk.sh "Reachy, look up"          # -> policy_denied, robot still
openshell policy set reachy-agent --policy openshell/policy-motion-enabled.yaml --wait
./talk.sh "Reachy, look up"          # -> completed, robot moves
openshell logs reachy-agent | grep -E "DENIED|ALLOWED" | tail

./voice.sh --once                    # press Enter, say it; Reachy moves and answers out loud
robot/venv/bin/python robot/listen.py   # hands-free; unaddressed speech -> (not for me)
